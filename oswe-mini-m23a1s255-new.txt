## How it works (short) 🔧
- Problem: baseline does open+write+flush+os.fsync() under a global lock for every request → high syscalls and lock contention.
- Optimization: move all log I/O to a single background writer thread that batches JSON lines and performs one write+fsync per batch.
- Correctness: CPU work is identical (reuses baseline compute), and deterministic fields (`job_id`, `length`, `vowels`) are preserved.
- Durability: an `atexit` drain ensures all records are persisted before process exit (so runner.py's behavior is preserved).
