# Immutable Baseline Optimization (mini‑prime)

This repository contains a small latency‑sensitive benchmark with an intentionally naive baseline (`baseline_worker.py`) and an optimized alternative (`optimized_worker.py`). The goal is to improve tail latency and throughput without changing the baseline files or the workload generated by `runner.py`.

Key files
- `baseline_worker.py` — Read‑only baseline implementation (do not modify).
- `optimized_worker.py` — Optimized implementation added for this exercise.
- `runner.py` — Workload generator and benchmark harness (do not modify).
- `run_tests` — One‑command script to run baseline and optimized runs, validate outputs, and produce `perf_report.json`.

Design summary (高层次说明)
- Bottleneck observed: baseline serializes every request's disk I/O using a global lock and performs an `open` + `write` + `flush` + `fsync` per request. Under concurrency this causes heavy syscall overhead and lock contention, which increases tail latency and reduces throughput.

- Key idea: defer and batch log I/O to a background writer that performs fewer, larger writes and fsyncs. Worker threads do the same deterministic computation and then enqueue structured records into a thread‑safe queue; a background thread accumulates records and writes them in batches, flushing and fsyncing periodically. This preserves logical outputs and eventual log durability while drastically reducing per‑request overhead and lock contention.

Reproducing the benchmark
1. Create a Python 3 virtualenv and activate it (optional):

   python -m venv .venv
   . .venv/bin/activate  # on POSIX
   .\.venv\Scripts\activate  # on Windows PowerShell

2. Run the unified test script:

   ./run_tests

This will run both the baseline and optimized workers via `runner.py`, validate the logs, print a short summary, and write `perf_report.json` at the repository root.

Results
- The `perf_report.json` file contains measured metrics for both implementations and derived speedups.

Measured result (on my machine):

| Implementation | Throughput (req/s) | p50 (s) | p95 (s) | p99 (s) |
|---|---:|---:|---:|---:|
| Baseline | 551.50 | 0.05613 | 0.06802 | 0.08454 |
| Optimized | 8880.55 | 0.00317 | 0.00450 | 0.01372 |

- Observed speedup (throughput): **~16.1x**

These numbers demonstrate a large reduction in tail latency and large increase in throughput by batching and deferring log I/O to a background writer while preserving correctness of recorded JSON lines.

Notes
- Only the Python standard library is used.
- The baseline behavior and workload are unchanged; the optimized path preserves the same set of log records and deterministic outputs.
